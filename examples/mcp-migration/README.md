# MCP Tool → Rotifer Gene Migration Examples

Three real-world MCP Tools migrated to Rotifer genes, demonstrating the `rotifer scan` → `rotifer wrap` workflow.

## Examples

| Tool | Domain | What it does |
|------|--------|-------------|
| [text-summarizer](text-summarizer/) | nlp | Summarize text passages |
| [url-fetcher](url-fetcher/) | network | Fetch web page content |
| [json-validator](json-validator/) | tooling | Validate JSON against a schema |

## File Structure

Each example contains:

```
<tool-name>/
├── mcp-tool.ts       # BEFORE: Original MCP Tool (Zod schema + handler)
├── index.ts          # AFTER:  Rotifer Gene (express() function)
└── phenotype.json    # Gene metadata (generated by rotifer wrap)
```

## Migration Steps

### 1. Start with your MCP Tool

A typical MCP Tool has a `handler` function, a `name`, and a Zod `inputSchema`:

```typescript
export const myTool = {
  name: "my_tool",
  inputSchema: z.object({ input: z.string() }),
  handler: async ({ input }) => {
    return { result: process(input) };
  },
};
```

### 2. Scan for candidates

```bash
rotifer scan path/to/your/tools/
```

The scanner detects exported functions and reports compatibility.

### 3. Wrap as a gene

```bash
rotifer wrap my-tool
```

This generates:
- `phenotype.json` with input/output schemas derived from your tool
- An `index.ts` with the standard `express()` entry point

### 4. What changes?

| Aspect | MCP Tool | Rotifer Gene |
|--------|----------|-------------|
| Entry point | `handler()` | `express()` |
| Schema | Zod runtime objects | JSON Schema in `phenotype.json` |
| Dependencies | Imported directly | Declared in `phenotype.json` |
| Execution | Direct function call | L2 sandbox with metering |
| Competition | None | Arena fitness ranking |
| Composition | Manual orchestration | Algebraic (`Seq`, `Par`, `Try`, etc.) |

### 5. Test and submit

```bash
rotifer test my-tool           # Sandbox validation
rotifer compile my-tool        # IR compilation
rotifer arena submit my-tool   # Enter the Arena
```

## Key Differences

**What stays the same:** Your core business logic. The `handler` body becomes the `express` body with minimal changes.

**What you gain:**
- Standardized metadata (`phenotype.json`) enables automated discovery, compatibility checking, and composition
- Arena competition drives quality — better genes surface automatically
- Algebraic composition (`Seq`, `Par`, `Cond`, `Try`) replaces manual orchestration
- L2 sandbox execution provides safety guarantees and performance metering
